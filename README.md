# Yandex.Disk Backup — массовое скачивание всего диска и безлимитного фото-хранилища

> **Готовый инструмент для миграции с Яндекс.Диска.** Скачивает обычные файлы через официальный REST API и скрытый безлимит (Photoslice — фото с телефонов) через куки браузера. Дедупликация по MD5, сортировка по полочкам, веб-интерфейс. Запуск одним кликом — зависимости ставятся сами.

**Ключевые сценарии:**
скачать всё с Яндекс.Диска · скачать безлимит Яндекс.Фото · бэкап перед отменой подписки · миграция с Yandex Disk на Google Drive / OneDrive / локальный NAS · экспорт фото с телефона из Яндекс.Диска · download Yandex.Disk Photoslice · Yandex Disk full backup tool

## Что умеет

| Возможность | Как работает |
|---|---|
| 💾 **Скачивание обычного диска** | Через официальный REST API Яндекс.Диска. Нужен OAuth-токен (получается в один клик) |
| 📸 **Скачивание безлимита** | Скрытое фото-хранилище Яндекса (Photoslice) — через куки браузера: mpfs/info → ссылка ORIGINAL → отдельный файл |
| 🗂 **Сортировка по полочкам** | Раскладывает файлы по типам: Фото/Видео/Документы/Архивы/… с подпапками по годам |
| 🧹 **Дедупликация** | Поиск совпадений по MD5; очередь не пропускает файлы без проверенной локальной копии |
| 🔄 **Resume** | Прерванное скачивание возобновляется с того же места. Хранит состояние в SQLite |
| 🌐 **Веб-интерфейс** | Тёмная тема в стиле Apple, открывается на `http://localhost:8000`, без эмодзи и шума |
| ⚡ **Параллельность** | До 5 потоков для обычного диска, до 6 воркеров для безлимита |
| 🛡 **Безопасность** | CSRF-защита, валидация путей, маскировка токена, atomic-write для куки |
| 🚀 **One-click** | Двойной клик по `webui.bat` — сам установит Python-зависимости и запустит браузер |

## Установка (1 минута)

### Шаг 1 — Установи Python (один раз, если ещё не стоит)

Скачай Python 3.10+ с [python.org/downloads](https://www.python.org/downloads/).
**При установке отметь галочку «Add Python to PATH»** — это важно!

### Шаг 2 — Скачай проект

```bash
git clone https://github.com/PXSYS13/yadisk_backup.git
```

Или просто скачай ZIP с GitHub (зелёная кнопка `Code → Download ZIP`) и распакуй.

### Шаг 3 — Запусти

**Windows:** двойной клик по **`webui.bat`**

**Linux / macOS:**
```bash
bash webui.sh
```

Скрипт создаёт `.venv` в папке проекта. На macOS достаточно установленного через Homebrew Python 3.10+; системный `pip` не используется.

При первом запуске скрипт:
1. Если `.venv` ещё нет, найдёт Python 3.10+ и создаст окружение
2. Проверит Python и `pip` внутри `.venv`
3. Установит недостающие библиотеки из `requirements.txt` в `.venv` (~1 минута)
4. Запустит сервер из `.venv`
5. Откроет браузер автоматически на `http://localhost:8000`

При следующих запусках всё это пропускается — сразу запуск сервера.

Для ручных команд активируйте окружение после первого запуска: `source .venv/bin/activate` (Linux/macOS) или `.venv\Scripts\activate.bat` (Windows cmd). Затем используйте `python` и `python -m pip` только в активированном окружении. Без активации укажите путь к Python: `.venv/bin/python` или `.venv\Scripts\python.exe`.

## Использование

### Вариант 1: один клик «Запустить» (рекомендую)

1. Открой вкладку **«Настройка»**:
   - Получи OAuth-токен на [yandex.ru/dev/disk/poligon](https://yandex.ru/dev/disk/poligon/) → жми «Проверить» → «Сохранить»
   - Укажи папку куда скачивать (например `D:/YandexBackup`) — **не указывай корень диска!**
   - Опционально: вставь cookies браузера для безлимита
2. Открой вкладку **«Главная»** → нажми **«Запустить»**
3. Программа сама всё сделает по очереди: scan → download → collect → workers

### Вариант 2: пошагово с выбором типов файлов

1. Вкладка **«Диск»** → **«Проверить диск»**
2. Когда сканирование закончится — появится список:
   ```
   📸 Фото        4 200 файлов  25 ГБ   [⬤]
   🎬 Видео         900 файлов  40 ГБ   [⬤]
   📄 Документы    200 файлов   1 ГБ    [ ]
   📦 Архивы        30 файлов   500 МБ  [ ]
   ⚙ Программы     50 файлов   80 МБ   [ ]
   ```
3. Переключатели — выбери что хочешь скачать (фото и видео включены по умолчанию)
4. **«Скачать выбранное»** — поедет

### Безлимит (фото с телефона)

Яндекс прячет фото с мобильных приложений в скрытом хранилище. Через REST API оно не отдаётся, но можно достать через куки браузера:

1. Установи расширение [Cookie-Editor](https://chromewebstore.google.com/detail/cookie-editor/hlkenndednhfkekhgcdicdfddnkalmdm)
2. Зайди на [disk.yandex.ru](https://disk.yandex.ru/client/disk), залогинься
3. Кликни иконку Cookie-Editor → **Export → Export as JSON**
4. В UI на вкладке **«Настройка»** в поле «Cookies» вставь JSON → **«Проверить»** → **«Сохранить»**
5. Вкладка **«Безлимит»** → **«Собрать список»** → **«Скачать выбранное»**

### Сортировка скачанного

Когда всё скачал — можешь автоматически разложить по полочкам:

1. Вкладка **«Сортировка»** → укажи папку с файлами
2. **«Только отчёт»** — увидишь сколько чего и сколько дубликатов
3. **«Применить»** — раскладывает в структуру:
   ```
   Папка/
   ├── Фото/2024/2024-08/...
   ├── Видео/2023/2023-07/...
   ├── Документы/
   ├── Архивы/
   ├── Программы/
   ├── Аудио/
   ├── Прочее/
   └── _duplicates/  ← дубликаты сюда (можешь потом удалить)
   ```

## CLI (если UI не нужен)

```bash
# Обычный диск
python main.py check                    # проверить токен
python main.py scan                     # быстро получить плоский список всех файлов диска
python main.py scan --root /Папка       # обойти только выбранную папку
python main.py download --workers 4     # скачать всё
python main.py retry-failed             # повторить упавшие
python main.py verify                   # проверить MD5
python main.py stats                    # статистика

# Безлимит (нужен cookies.json)
python unlim_download.py --collect      # собрать список
python unlim_worker.py --id 1           # один проход; failed повторятся при следующем запуске
# Для параллельного запуска вручную: одинаковый НОВЫЙ run-id для всех воркеров прохода
python unlim_worker.py --id 1 --run-id backup-20261012-1
python unlim_worker.py --id 2 --run-id backup-20261012-1
# ...

# Сортировка
python organize.py --input "D:/Backup"                  # отчёт
python organize.py --input "D:/Backup" --action move    # применить
```

Сбор безлимита берёт состав файлов из общего индекса photoslice. Отдельный запрос состава нужен только для кластеров, где индекс не вернул список файлов; размеры и доступность уточняются при скачивании. `python main.py scan` получает все файлы обычного диска через плоский список API; `--root` и `--roots` для выбранных папок используют обход дерева.

Быстрый индекс безлимита может не содержать размеры файлов. Интерфейс отдельно показывает известный объём и число файлов без размера, а не считает неизвестные размеры нулевыми. Воркер сохраняет полученный размер до начала передачи файла; он остаётся известным и после ошибки передачи. Точный общий объём заранее нельзя получить из такого индекса: для этого потребовались бы дополнительные запросы метаданных, которые увеличивают время сбора и могут не сработать для недоступных файлов.

## Часто задаваемые вопросы

### Запустил `webui.bat`, а он говорит «Python is not installed»

Установи Python с [python.org/downloads](https://www.python.org/downloads/) и **обязательно** отметь галочку «Add Python to PATH» при установке. После этого закрой все cmd-окна и запусти `webui.bat` снова.

### Установка зависимостей зависла

Проверь интернет. Если медленный — установка в `.venv` может занять до 5 минут.

### При запуске пишет «Failed to install dependencies»

Скорее всего `pip` не имеет доступа в интернет (фаервол / прокси). Попробуй вручную из папки проекта:
```bash
.venv/bin/python -m pip install -r requirements.txt  # Linux/macOS
# Windows cmd: .venv\Scripts\python.exe -m pip install -r requirements.txt
```
Если ошибка повторится — скриншот в issue на GitHub.

Если скрипт сообщает, что `.venv` повреждено, переименуйте его для сохранения или удалите вручную и запустите `webui.sh` / `webui.bat` снова.

### Сервер запустился но браузер не открылся

Открой вручную: http://localhost:8000

### Скачивание прерывается

- **БД сохраняет прогресс** на каждом файле — просто запусти скачивание снова, оно продолжит
- Если совсем застряло — нажми кнопку **«Очистить и заново»** в карточке «Что нашлось»

### Токен перестал работать

OAuth-токен Яндекса живёт примерно год. Получи новый на [yandex.ru/dev/disk/poligon](https://yandex.ru/dev/disk/poligon/) и сохрани через UI (кнопка «Удалить» рядом со старым → вставь новый).

### Cookies перестали работать (для безлимита)

Сессионные куки браузера живут несколько часов / дней. Зайди в браузере на disk.yandex.ru заново, экспортируй cookies снова через Cookie-Editor и обнови в UI.

### Яндекс блокирует на 429 (Too Many Requests)

- Снизь `MAX_WORKERS` до 2-3
- Подожди 10-15 минут и попробуй снова
- Программа сама делает паузы при 429

### Указал DOWNLOAD_DIR=C:\ и сервер виснет

Программа защищена от этого — не обходит корни дисков. Укажи конкретную подпапку, например `C:/YandexBackup`.

### Безопасно ли использовать?

- ✅ **Токен и куки** хранятся только локально на твоём диске (`.env` и `cookies.json`)
- ✅ Эти файлы в `.gitignore` — не попадут в git
- ✅ Web-UI слушает только `127.0.0.1` — недоступен из интернета
- ✅ CSRF-защита: чужой сайт не сможет дёрнуть API
- ✅ Path traversal: нельзя сортировать системные папки (`C:/Windows` и т.д.)
- ⚠️ Безлимит через куки — серая зона по ToS Яндекса. Используй **только для своих данных** перед отменой подписки

## Пофайловое скачивание и недоступные файлы

Безлимит больше не использует ZIP и `bulk-download-prepare`. Воркер получает метаданные одного файла через `mpfs/info`, выбирает только `meta.sizes[name=ORIGINAL].url` и скачивает оригинал. Контракт взят из [исходников независимого клиента](https://github.com/delorum/yaDiskUnlimDownloader/blob/main/src/main/scala/yaDiskUnlimDownloader/api/YandexDiskApi.scala#L65-L73). Это внутренний API: на вашем аккаунте его необходимо проверить небольшим запуском. Для видео наличие ORIGINAL не гарантируется; при отсутствии ссылки файл остаётся `failed`, превью вместо него не сохраняется.

В `.env` доступны настройки для обычного диска и безлимита:

```dotenv
DOWNLOAD_CONNECT_TIMEOUT=5
DOWNLOAD_READ_TIMEOUT=15
UNLIM_TIMEOUT_RETRIES=0
```

Эти же значения можно изменить в «Настройка → Таймауты сети». Допустимы числа от 0,1 до 3600 секунд. Настройки сохраняются в `.env` и действуют для новых задач; уже запущенную задачу нужно остановить и запустить заново.

Сервер пишет диагностику в stdout: запуск и завершение задач с PID и кодом выхода, вывод дочерних процессов, этапы pipeline и медленные HTTP-запросы. Каждые 30 секунд появляется `server_heartbeat`, а для активных задач — `task_status` с `elapsed_s` (время работы) и `idle_s` (время без вывода). Долгое молчание само по себе не доказывает зависание. HTTP-запросы, которые ещё выполняются, отмечаются префиксом `http:`; для них время молчания совпадает с временем ожидания ответа. Токены, cookies и URL в диагностике маскируются.

Это таймаут подключения и допустимая пауза без данных на запрос, а не ограничение общей длительности скачивания большого видео. Получение метаданных и загрузка файла — отдельные запросы; их время может суммироваться. Для безлимита настройка «Повторы при таймауте» (`UNLIM_TIMEOUT_RETRIES`, целое число 0–10) задаёт число дополнительных попыток: 2 означает до 3 попыток всего, 0 отключает повторы. По умолчанию 0. Повторяются только таймауты получения метаданных и передачи файла; перед повтором незавершённый `.part` удаляется и ссылка запрашивается заново. После исчерпания попыток, а также при 404, отказе ресурса или 5xx, воркер сохраняет ошибку в SQLite и переходит к следующему файлу. Скачивание обычного диска эта настройка не меняет. Следующий запуск автоматически пробует `failed` снова. Для безлимита общий `--run-id` не даёт другому воркеру немедленно повторить тот же файл; веб-интерфейс создаёт новый общий ID сам. При ручном перезапуске используйте новый ID или запускайте один воркер без этого флага.

Истёкшая авторизация/CKEY/CAPTCHA останавливает воркер с объяснением. HTTP 429 приостанавливает новые запросы с учётом Retry-After, чтобы не увеличивать ограничение сервера. Ошибка локального диска также останавливает воркер. Недоступные файлы сохраняют ID, причину, число попыток и ID последнего прохода в `unlim_state.db`; очищать БД для повтора не нужно.

Индекс фото может включать и обычный диск (`/disk/`), и безлимит (`/photounlim/`). Среди ожидающих заданий воркеры сначала обрабатывают безлимит; записи обычного диска остаются в очереди. Серия пропусков 404 в stdout сворачивается в периодические сводки; таймауты и другие ошибки выводятся сразу. Консоль безлимита объединяет события воркеров по времени. Номера попыток, этапы, ошибки и повторы записываются в `logs/unlim_worker.log`, а окончательный результат — в БД. Ответ `mpfs/info: HTTP 404` означает, что API не нашёл ресурс по запрошенному пути; сам по себе он не доказывает потерю файла или сбой всего API. Если сервер передал безопасный код ошибки, он добавляется к сообщению, например `API 70`.

Проверенные файлы публикуются через `.part` → проверка размера/MD5 (если предоставлен) → атомарная замена. В безлимите сохраняется локальный SHA-256. Разным remote ID назначаются разные пути; совпадение имени и размера больше не означает совпадение файлов.

### Обновление старой установки

1. Остановите старый веб-интерфейс и все старые воркеры перед заменой кода.
2. Сохраните резервную копию `state.db` и `unlim_state.db` после остановки процессов (при наличии WAL сохраняйте согласованный снимок через SQLite backup).
3. Обновите зависимости в окружении проекта: `.venv/bin/python -m pip install -r requirements.txt` (Linux/macOS) или `.venv\Scripts\python.exe -m pip install -r requirements.txt` (Windows). Если `.venv` ещё нет, запустите `webui.sh` / `webui.bat` один раз.
4. Запустите `python unlim_download.py --collect`, затем `python unlim_worker.py --id 1`, либо обычный запуск в веб-интерфейсе. Если сбор списка завершился частично, известные файлы можно скачать, затем повторить сбор.

Миграция добавляет служебные столбцы автоматически. Старые `downloaded` без `local_path` из ZIP-режима возвращаются в очередь: прежний код мог ошибочно отметить всю пачку скачанной. Старые локальные файлы не удаляются; новые оригиналы размещаются в `_unlim/<ID-prefix>/<ID-hash>/<имя>`, поэтому на переходный период может потребоваться дополнительное место. После аварийного убийства процесса его задания становятся доступными после истечения аренды (до 180 секунд); обычная остановка возвращает текущее задание сразу, если ОС даёт процессу выполнить обработчик завершения.

Общий pipeline обрабатывает доступные файлы следующих этапов даже после частичных ошибок. Итог при незавершённой копии — «завершено не полностью», а не «всё готово». Коды CLI: 0 — успех, 1 — остались ошибки/неполный результат, 2 — требуется устранить общую проблему, 130 — прерывание.

Тесты используют временные файлы/SQLite и подставные ответы HTTP, не подключаются к аккаунту и не скачивают ваши фотографии. Они проверяют таймауты без повторов, пропуск недоступного файла и повтор в следующем запуске, параллельные задания, целостность и атомарную запись, миграцию старой БД и правдивые статусы интерфейса.

## Требования

- Python 3.10+ (с pip — он почти всегда идёт в комплекте)
- Windows / Linux / macOS (тестировалось на Windows 11)
- ~150 МБ для зависимостей
- Свободное место на диске под бэкап (от 1 ГБ до 200+ ГБ в зависимости от данных)
